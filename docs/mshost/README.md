# MSHost Talk Android

Отдельный Android-клиент разговоров и звонков, основанный на Nextcloud Talk
Android `25.1.0`, commit `ed682a94a27813efc71b759917e9d8033f748f29`.
Поддерживаемый вариант форка — `genericRelease`, версия `25.1.0`,
versionCode `250010090`, Android 8.0/API 26 и новее.

Исходники MSHost публикуются в ветке `mshost` собственного
[форка](https://github.com/BigShiShKa/mshost-talk-android/tree/mshost).
`master` сохраняет более новый upstream; это другая база, чем текущая сборка.

Перед публикацией 15 ноября 2026 повторно прошли `python branding/test_branding.py`,
`detekt ktlintCheck --offline -PmshostMavenMirror=true` и `verify-release.py`
на сохранённом APK 25.1.0. Проверен перечень публикуемых исходников и отказ
экспорта при постороннем файле/приватном ключе. Gradle использовал актуальные
локальные результаты (`UP-TO-DATE`). APK не пересобирался, на телефон не
устанавливался; это не проверка звонков или внешней сети.

## Брендинг и изоляция

- Имя: MSHost Talk; пакет: `org.mshostcloud.talk`.
- Тип аккаунта и MIME-тип записей контактов отделены от оригинального Talk.
  Namespace исходников `com.nextcloud.talk` оставлен upstream.
- Provider и локальные разрешения используют штатный `${applicationId}`.
- Сервер `https://cloud.mshostcloud.org` задан штатным `weblogin_url`:
  при открытии экрана выбора сервера начинается проверка и переход ко входу.
- Импорт аккаунтов файлового клиента отключён; вход выполняется отдельно.
- Логотип Talk — белая монограмма **MT** (MSHost Talk) в облаке с градиентным
  бирюзово-сине-фиолетовым контуром. Векторный источник `branding/talk-logo-mt.svg`,
  подготовленный PNG `branding/talk-logo-mt.png`. Из PNG генерируются launcher,
  адаптивная иконка и логотип экрана входа/запуска. PNG включён в исходники,
  поэтому Android-сборка не зависит от установки инструментов Desktop.
- Протоколы входа `nc://` и ссылок `nextcloudtalk://` сохранены для совместимости.
- Юридические уведомления и GPL-3.0-or-later сохранены. Ссылка на исходники в
  настройках ведёт в upstream; соответствующие исходники MSHost приложены к APK.

## Сборка

Используются JDK 21, Android SDK 37, Gradle 9.8.1 и версии плагинов upstream.
Нужны Python 3, PowerShell и System.Drawing; дополнительные Python-пакеты не нужны.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File branding/build-local.ps1 -Checks
```

Скрипт генерирует иконки, проверяет согласованность пакета/аккаунтов/контактов,
собирает APK и с `-Checks` запускает `detekt ktlintCheck`. Экспортирует APK,
исходники, сведения о сборке и SHA-256 в
`D:\MSHost\Builds\TalkAndroid\dist\25.1.0`.

### Выпуск 25.1.0, 14 ноября 2026

Release-вариант без alpha/debug-метки. Отладчик Java и JNI отключены;
`BuildConfig.DEBUG=false`, скомпилированный `nc_is_debug=false`. Проверяются
отсутствие test-only/profiling-флагов, инструментов Compose UI inspector,
тестовой Activity и стартового Toast с flavor. Уровень штатного логирования
по умолчанию — WARNING. Обычная диагностика и проверка push сохранены.
Минификация оставлена в штатной конфигурации upstream; отсутствие debug-функций
проверяется в APK, а не предполагается по имени файла.

`branding/verify-release.py` проверяет APK и сгенерированный release BuildConfig;
на прежнем debug APK alpha.2 проверка отклоняет Compose inspector.
Первая проверка release также обнаружила тестовую Activity: upstream-зависимость
`androidx.test.ext:junit-ktx` была подключена как `implementation`. Она перенесена
в `androidTestImplementation`; в основном коде её импортов нет. Аналогично перенесён
`androidx.room:room-testing-android`, используемый только тестами миграции базы.
Проверка APK подтверждает отсутствие тестовой Activity и MigrationTestHelper
после пересборки.
Сертификат выпуска и цепочка ротации сохранены, versionCode повышен выше alpha.3.
Обновлять поверх существующего MSHost Talk без удаления приложения.
На физический телефон агентом выпуск не устанавливался.

Для Maven Central применяется явная опция `-PmshostMavenMirror=true` с зеркалом
`https://maven-central.storage-download.googleapis.com/maven2/`.
Gradle Plugin Portal используется для plugin markers; обычные зависимости
плагинов разрешаются через Google/Maven. Это сохраняет ожидаемые upstream POM
marker-файлы и обходит 403 от прямого Maven Central. Без опции остаётся обычная
конфигурация репозиториев. Проверки SHA/PGP не отключаются.

Начиная с alpha.3 APK собирается как release без `debuggable` и подписывается
отдельным ключом выпуска RSA 3072. Старый сертификат alpha.2 сохранён в цепочке
ротации: Android 9+ использует новый ключ через v3, Android 8 — прежний через v2.
Пакет сохранён, versionCode повышен; обновлять поверх alpha.2 без удаления приложения.
Криптографическая цепочка и подписи проверяются apksigner; реальное обновление
с сохранением аккаунта на телефоне пока не проверено (подключённых ADB-устройств нет).

Приватные материалы находятся в `Builds/TalkAndroid/signing`, вне исходников
и выпусков: `release.p12`, защищённая копия `legacy.p12`, `lineage.bin`,
`password.dpapi`. ACL ограничен текущим Windows-пользователем, пароль случайный
и защищён DPAPI. Внешняя восстанавливаемая резервная копия ключей пока не проверена;
DPAPI-файл привязан к текущему пользователю Windows и сам по себе не является
переносимой резервной копией. Ключи и пароль нельзя добавлять в source.zip.

`branding/initialize-signing.ps1` выполняется один раз и отказывается перезаписывать
существующий каталог. `branding/sign-release.ps1` используется сборкой для подписи
с цепочкой ротации. Сертификат выпуска SHA-256:
`2c1b16daafafe6ee3b06fbd14084c53b3090da40790e20064c7cd4b69f32f5f8`.

Экспорт исходников использует явный перечень `branding/source-files.json`,
отклоняет неожиданные файлы и приватные ключи. В релизном README исправлено
описание push: при Google Play services доступен встроенный distributor Web Push.

## Уведомления и входящие звонки

Вариант generic этой версии содержит `embedded-fcm-distributor:3.1.0`.
При наличии Google Play services он может использовать встроенный distributor
для Web Push. Отдельный внешний distributor не обязателен. Без Google Play
services можно использовать совместимый внешний UnifiedPush distributor.
Предыдущее указание об обязательной установке отдельного distributor было неточным.
В обоих случаях сервер должен объявлять capability `notifications.push=webpush`.

Штатная инструкция upstream: [UnifiedPush](../unifiedPush.md),
[проверка уведомлений](../notifications.md).

1. В Nextcloud: администрирование → Уведомления → разрешить Web Push.
2. Если диагностика показывает встроенный distributor, сначала использовать его.
   После включения Web Push обновить данные аккаунта; при необходимости выполнить
   повторную авторизацию аккаунта в Talk, чтобы повторить регистрацию push.
3. Если встроенного distributor нет, установить внешний (например Sunup из
   штатной инструкции), затем в Talk включить UnifiedPush и выбрать сервис.
4. Разрешить уведомления, микрофон/камеру по необходимости, проверить настройки
   фоновой работы и вызов при заблокированном экране из другой сети.

Наличие APK и успешная проверка подписи не доказывают работу входящих звонков,
push, микрофона, камеры или демонстрации экрана на конкретном телефоне.
Автоматическая установка на телефон и публикация APK на сервере не выполняются.

### Диагностика отсутствия входящего вызова, 13 ноября 2026

В присланном отчёте alpha.2 на Android 15 разрешения уведомлений, канал звонков
и показ поверх блокировки включены, ограничения батареи сняты. Встроенный
distributor обнаружен, но `Server supports webpush? = No`, push endpoint неизвестен.
`UnifiedPush services = 0` считает внешние distributor и само по себе не означает
отсутствия встроенного. `Use UnifiedPush = No` также не доказывает отсутствие
встроенного пути: это настройка внешнего distributor.

В коде регистрация через встроенный distributor пропускается, когда аккаунт
не имеет Web Push capability. После разрешения Web Push одного перезапуска
приложения оказалось недостаточно: повторная авторизация аккаунта через браузер
запустила регистрацию. В отчёте 03:21:51 выбран сервис `org.mshostcloud.talk`,
endpoint получен в 03:21:03, но доставка ещё не работала.

Серверный тест показал `No devices left after filtering`; проверка базы подтвердила
подписку `app_types: talk`, `activated: false`. После повторной отправки служебного
push активации через серверный WebPushClient (`success: true`, HTTP `201`)
пользователь сообщил: «Все заработало». Причина сбоя первой активации не установлена;
отдельного вывода `activated: true` не предоставлено. Пересборка APK и внешний
distributor не потребовались. Работа после длительного простоя, при блокировке
и смене сети отдельно не подтверждена.

Результат актуализирован 14 ноября по переписке, без повторной проверки телефона.
[Канонические серверные команды диагностики и повторной активации](../../../../Documentation/MSHost-Cloud/docs/talk.md#проверка-и-повторная-отправка-активации).

Архив содержал одну запись `Unexpected notification ui state: None` из экрана
диагностики; это не журнал обработки входящего звонка и не доказательство
причины отсутствия звука. Сырые логи и данные аккаунта в документы не включены.
